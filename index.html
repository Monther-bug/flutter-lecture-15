REST API: every thing (a resource: posts, users, todos) has its own URL.

The method says what you want to do with it:

dynamic means Dart does not know the type until the app runs, so it cannot warn us about mistakes. That is fine today; in Lecture 22 we fix it with model classes. as tells Dart "trust me, this is a Map" (or a List).

Before you code

Look before you code: open the URL in a browser

Before writing code, answer three questions

  1. Does it start with [ (a List) or { (a Map)?
  2. Which keys do I need? (id, title, body)
  3. What type is each value? (id is a number, title is text)
/postsstarts with [ → a list of 100 post maps
/posts/1starts with { → one post map

Permission to use the internet

AndroidManifest.xmlthe main one
<!-- android/app/src/main/AndroidManifest.xml -->
<manifest xmlns:android="http://schemas.android.com/apk/res/android">
    <uses-permission android:name="android.permission.INTERNET" />

    <application
        ...
android/app/src/
├─ debug/AndroidManifest.xmlINTERNET ✓ (flutter run)
├─ profile/AndroidManifest.xmlINTERNET ✓
└─ main/AndroidManifest.xmlrelease APK: add it here
Android: put this line in the main manifest, above <application>.

Why debug works without it: Flutter puts INTERNET in src/debug/ and src/profile/ only (hot reload needs it). A release APK uses only src/main/, so without the line: no internet.

iOS: nothing to add for https:// URLs.
macOS desktop only: in macos/Runner/DebugProfile.entitlements and Release.entitlements add <key>com.apple.security.network.client</key><true/>.
Mobile App Development · Lecture 15

Open android/app/src/debug/AndroidManifest.xml and read its comment ("required for development… hot reload"). Classic story: "it works on my phone with flutter run, but the APK I sent to my friend shows no data". Add the line once now and forget about it.

Always use https://: Android and iOS block plain http:// by default.

Future: a value that comes later

Some jobs take time: downloading, reading a file, waiting for a server. A Future is a promise: “I don't have the value yet, but I will.”

1 · You order

at the counter of the restaurant

2 · You get a buzzer

the Future. You sit down and do other things.

3 · It buzzes

the food is ready: now you have the value

lib/pages/future_demo_page.dart
// A pretend slow job: 3 seconds, then a String.
Future<String> makeTea() async {
  await Future.delayed(const Duration(seconds: 3));
  return 'Your tea is ready';
}
Future<String>a String, later
Future<List<dynamic>>a list, later
Future<void>“done” later, no value
http.get(...) gives us a buzzer too: a Future<Response>.

Demo · The Posts page

Your first GET request

lib/pages/posts_page.dartat the top
Future<List<dynamic>> fetchPosts() async {
  final url = Uri.parse('https://jsonplaceholder.typicode.com/posts');
  final response = await http.get(url);

  if (response.statusCode == 200) {
    return jsonDecode(response.body) as List<dynamic>;
  } else {
    throw Exception('Failed to load posts (${response.statusCode})');
  }
}
1Uri.parseturns the text into a URL object (http.get needs a Uri, not a String)
2await http.get(url)send the GET request and wait for the response
3statusCode == 200only then use the body
4jsonDecode(response.body)JSON text → a Dart List
5throwstop and report a problem (the screen will show it)

FutureBuilder rebuilds itself when the Future finishes, so we don't call setState. Never write future: fetchPosts() inside build(): every rebuild (hot reload, rotating the phone) would start a new request. late means "I will give it a value before I use it" (in initState).

Wrap-up

Summary + Questions

Today you learned

  • An API is the waiter between your app and a server; REST = URLs + methods.
  • Request = URL, method, headers, body. Response = status code, headers, body.
  • JSON { } → Map<String, dynamic>, [ ] → List<dynamic>, with jsonDecode.
  • async/await wait for a Future without freezing the app.
  • http.get → check statusCode → jsonDecode → show it with FutureBuilder.

Don't forget

The INTERNET permission goes in the main manifest, or the release APK has no internet.
Start the Future in initState(), not with future: fetchPosts() inside build().
